# DUSK — Claude Code Instructions

## Project in one line

Behavioural threat detection for agentic networks. Python 3.11+, package `dusk-security`, CLI `dusk`. Catches hijacked AI agents by comparing their actions against a learned per-agent baseline — not credentials, behaviour.

## Architecture — two detection layers

### Layer 1: Network (v0.1, shipped)
- Reads pcap files via `scapy`
- Detections: sweep, boundary crossing, lateral movement, telemetry anomaly
- CLI: `dusk scan --file <pcap>`
- Output: ALERT / CLEAR verdict with Rich terminal output or JSON

### Layer 2: Agent action gate (v1.1, shipped)
- Ingests control-plane actions (firewall rule changes, route changes, role assignments, port changes)
- Normalises via source adapters (Azure, generic)
- Learns per-agent baseline from known-good actions
- Scores new actions: anomaly score 0–1, reasons, MITRE ATT&CK + ATLAS, blast radius
- Verdicts: ALLOW / WOULD-BLOCK (watch mode default) / BLOCK (enforce mode)
- CLI: `dusk gate --baseline <file> --check <file>`

The key insight: SIEM asks "is this allowed?" — DUSK asks "does this agent normally do this?" A hijacked agent with valid credentials looks legitimate to SIEM. Only its behaviour gives it away.

## Key data types

### AgentAction (src/dusk/actions/event.py)
```
agent_id: str
timestamp: datetime (timezone-aware)
action_type: str  # firewall_rule_change | route_change | segment_change |
                  # role_assignment | port_change | unknown
target: str
change: dict      # {before: ..., after: ...}
source: str       # adapter name
raw_ref: str      # opaque original record ID
```

### AnalysisResult (src/dusk/actions/analyse.py)
```
agent_id, action_type, target
score: float       # 0..1 anomaly score
reasons: list[str]
mitre_attack: str  # e.g. T1562.004
mitre_atlas: str   # e.g. AML.T0051
blast_radius: str  # LOW | MEDIUM | HIGH | CRITICAL
predicted_next: str
```

### VerdictResult (src/dusk/actions/verdict.py)
```
verdict: str       # ALLOW | WOULD-BLOCK | BLOCK
refused: bool
analysis: AnalysisResult
```

## SVG/HTML asset rules

- No `<script>` tags in SVGs (GitHub strips them)
- No external `href` references in SVGs (GitHub blocks them)
- Entity-encode `&` as `&amp;` in SVG XML
- Use `&#10003;` for checkmarks in SVG
- Transparent outer background (no fill on root `<svg>`) so assets float on GitHub light/dark themes
- CSS-only animation: `@keyframes`, `stroke-dashoffset`, `animateMotion` with `<mpath href="#internal-id"/>`
- f-string brace rule: `{VAR}` consumes its closing `}`, so `{VAR}}}}` leaves only `}}}` — one stray `}` crashes the f-string. Split into `f"...{VAR}}"` + `"}}"` when in doubt.
